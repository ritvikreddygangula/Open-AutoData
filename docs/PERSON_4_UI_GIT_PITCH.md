# PERSON_4_UI_GIT_PITCH.md

## Your Role
You are the Pitch & Repository Director. Your objective is to build the visual proof of the system, maintain the GitHub repository, and frame the final submission for the hackathon judges.

## Instructions for Claude Code
1. Read `MASTER_SPEC.md` for project context, the agents, and the record contract (§5).
2. Build the website in `site/` (Next.js, static export) that polls `data/trajectories.json` for the live run log and `data/benchmark.json` for the benchmark card.
3. Design the UI to show top-level metrics (rounds, accepted pairs, average gap, rounds per accepted pair) and an expandable feed of live agent attempts showing the Weak vs. Strong score bars.
   - Each round has 3 weak and up to 3 strong attempt scores (`weak_attempt_scores`, `strong_attempt_scores`); show them, not just the averages.
   - `weak_*` / `strong_*` fields are empty when a round failed the quality check (`FAILED_QV`) or hit a model error, so handle missing values.
   - Show `failure_mode` (`TOO_EASY`, `TOO_HARD`, `FAILED_ON_STRONG`, `FAILED_QV`) and `fail_reason` per round, plus the `context`, `question` and `rubric` the solvers saw. The "rejected, rejected, accepted" story per chunk is the demo.
4. Draft a comprehensive `README.md` formatted for a hackathon submission. Explicitly state compliance with the Agent Skill Open Standard and the Snowflake track, and cite the Autodata paper (arXiv 2606.25996) as the method we implement.
5. Include placeholder sections in the README for the Mermaid architecture diagram (reference `Data_flow.png`; note the paper adds a quality-verifier step between challenger and solvers) and the benchmark chart generated by Person 3.
